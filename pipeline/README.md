# Content pipeline

A Node CLI (run with tsx) that researches, drafts, checks and publishes pages into the content Sheet. `.github/workflows/pipeline.yml` runs it weekly (Sundays, 02:00 UTC): `tours:check` and `tours:describe` for the owner's tours (see Tours below), then `refresh`, which re-researches published rows past `refresh_after`, and `publish`, which puts the refreshed pages that pass check live. New Queue rows are run locally (or by hand) with `run`.

```sh
npm run pipeline -- init                 # create the Queue, Facts and Queries tabs
npm run pipeline -- research 5           # up to 5 queued rows
npm run pipeline -- draft 5
npm run pipeline -- check 5
npm run pipeline -- publish 5
npm run pipeline -- refresh 5            # published rows past refresh_after
npm run pipeline -- run --max 30         # research, draft, check, publish under one budget
npm run pipeline -- seed --file pipeline/launch-queue.json   # append Queue rows (skips existing ids)
npm run pipeline -- images 20            # hero images for published rows with no hero_image
npm run pipeline -- images 5 --dry-run   # same, but files land in pipeline/.dry-run/images-<time>/
npm run tours:import                     # Tours_Inbox URLs -> draft Tours rows (also: npm run pipeline -- tours:import)
npm run tours:check                      # follow every published tour's /go/ link
npm run tours:describe                   # best_for / why_picked for published tours missing them
npm run tours:queue                      # ranked_list Queue rows for region + category with 3+ tours

# Read the Sheet, call the API, write nothing. Drafts land in pipeline/.dry-run/<time>/.
npm run pipeline -- run --max 3 --dry-run --queue-file pipeline/fixtures/dry-run-queue.json
```

Options: `--max <n>` (or a positional `n`), `--dry-run`, `--no-redraft` (check only), `--queue-file <json>` (dry runs only: Queue rows from a file instead of the tab), `--only <id,id>` (Queue ids; for `images`, row slugs), `--budget <usd>`.

## Rules the pipeline keeps

- **Sheet access.** The pipeline's only Sheet code is `pipeline/sheet.ts`, using its own write-enabled service account. The site still reads only through `lib/sheets.ts` with the read-only account. Rows are validated with the site's own schemas in `lib/sheet-schema.ts`.
- **Tours are the owner's.** `draft` filters the owner-curated Tours tab (published rows matching the page's region, town and Queue `category`) in the owner's `rank` order. It never adds, chooses or reorders tours, and `check` rejects any `<TourCards>` id that isn't a published, curated row. A ranked list with no matching tours goes to `needs_review` instead of being drafted.
- **No thin pages.** Before drafting, a fact sheet with fewer than 12 sourced facts, or a town page or guide with no sourced route from Paris, goes straight to `needs_review` with the reason in `findings`; no draft tokens are spent.
- **One automatic research retry.** If the fact sheet is too thin for the gate, or nothing usable comes back, research runs once more with a hint to start from the tourist office's estate and visit listings. The attempt with more facts is kept; both are logged in `usage_json` (`research`, `research-retry`).
- **The wine first on region and wine-area pages.** Research for those pages starts with the wine (grapes, appellations, classifications, soils, styles) from the Comité Champagne, CIVB, BIVB, INAO and appellation bodies, then estates and visits, then getting there; up to 15 `other_facts`.
- **Regions first.** Wine areas and towns are hidden on the site until their region is published, so `publish` publishes regions first and holds a wine area or town in `checked` until its region is live; a later publish picks it up. Held rows don't count toward `--max`.
- **Official visits are fine in prose.** Drafts may name non-commercial official tours and visits (tourist offices, the Cité du Vin, interprofessions, estates' own visits) without a card. Commercial tours appear only through curated `<TourCards>`; ranked lists mention no tour outside the brief.
- **Sourced facts only.** Research facts must cite a URL that web search actually returned in that run; anything else is dropped (the Facts tab's `dropped_json` lists what). Research gets 8 searches per row, spent in order: the Paris route and nearest station, then estates and visits, then opening months and prices, and the domains in `content/research-blocklist.txt` (Rome2rio, Tripadvisor, Wanderlog, booking platforms and similar) are excluded from search and never count as a source. The writer and checker see the fact sheet without its source URLs. Drafts may only use numbers from the fact sheet, tours and hotels; `check` enforces it.
- **Two checks must agree.** Each draft is graded by two independent check passes. A model error blocks the draft only when both passes report it (same rule, overlapping quote); a finding from one pass alone is kept as a warning, so the writer still sees it on a redraft. Deterministic checks always block.
- **Live pages never show unchecked drafts.** Every draft is stored in `Queue.draft_json`. It is also written to the content tab straight away, but only while that row isn't published. `publish` copies the checked draft over, so a refresh of a live page only goes live once it passes.
- **Dry runs can't write.** `--dry-run` requests a read-only OAuth scope, records every planned write in `writes.json` and skips the revalidate call.

## Stages

```
queued ──research──▶ researched ──draft──▶ drafted ──check──▶ checked ──publish──▶ published
                                              ▲   │ fail: redraft with findings (up to 2×)
                                              └───┘ third fail ──▶ needs_review
any stage ── unrecoverable error ──▶ error (message in the error column)
published ──refresh (facts changed)──▶ researched ──▶ … ──▶ checked ──▶ published
```

| ---------- | --------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------- |
| `research` | `queued`                                            | Sonnet-class model with web search (8 searches, blocklisted domains excluded) and `content/prompts/research.md`. Writes the fact sheet to Facts.                                                                                                                                                                              | `researched`                                      |
| `draft`    | `researched`                                        | Builds the prompt from `prompts/draft.md`, `style-guide.md`, `banned-phrases.txt`, `templates/{page_type}.md` (towns use `town.md`) and the fact sheet. ### What `check` grades

Deterministic (`pipeline/lib/checks.ts`), each failure an error:

- every number in the title, standfirst, meta description, body and FAQ appears in the fact sheet, tours, hotels (or, on ranked lists, the selection rules). Allowed extras: a USD amount in parentheses within 6% of an allowed EUR amount at `PIPELINE_EUR_USD_RATE`, the hours and minutes of a duration in minutes, ranked-heading numbers and `Day n` labels;
- no banned phrase (`...` in the list matches a short gap);
- body word count within the template's `words` range;
- required H2 headings and components present; no H1; at most `max_tables` tables (default 1), no Markdown pipe tables;
- every `<TourCards>` id is a published Tours row curated for this page; every `<HotelCards>` id is in Hotels; no raw GetYourGuide, Viator, Booking.com, Expedia or Winalist URLs;
- ranked lists: exactly one H2 per curated tour, titles matching, in rank order;
- no "I", "my" or "me", and no "we", "our" or "us" outside a `<MethodologyBox>`;
- no wine-selling language ("buy bottles", "ship them home", discount codes);
- no meta-language about how the page was made ("fact sheet", "not sourced", "unconfirmed", "the sources") or about where a fact was found ("one source says", "reportedly", "according to", "is described as", "the listing shows", "lists … on the … page"); ordinary uses such as "the source of the grapes" pass;
- at most two "ask the estate / check with the tourist office" lines on the page, FAQ included (table cells don't count);
- no administrative or road trivia (population, postcodes, cantons, "RN 3");
- no 24-hour clock times ("9:00", "14:30", "14h30"); write "9 a.m.", "2:30 p.m.";
- every euro amount followed by its USD conversion, "€25 ($27)";
- American English words and spellings ("rental car" not "hire car", "center" not "centre", "meter" not "metre"); FAQ questions may use "I" ("Do I need to book?"), nothing else may.

The model then grades the same rules plus unsourced claims and style. A draft passes when there are no deterministic errors, the model passes it, and the score (the model's score minus 10 per deterministic error) is at least `PIPELINE_PASS_SCORE` (default 80).

## Hero images (`images`)

`images [n]` gives up to n published Regions, SubRegions, Towns and Articles rows with an empty `hero_image` a hero photo, a tab at a time in that order, so parents are done before their children. It doesn't touch the Queue. **It never generates images**, and every row and Images line it writes has `hero_is_ai` / `is_ai` set to `FALSE`.

1. **Search** each source separately, first with the specific queries from `searchQueries` (place name + "vineyards", "vignoble"/"vignes"; for articles the title's subject, then the region), and score 8 candidates: up to 3 stock photos (Pixabay, then Pexels) always get a place, Commons fills the rest and comes first, and either side fills places the other leaves empty (`mixCandidates`):
   - **Wikimedia Commons** API with a descriptive User-Agent carrying `IMAGES_CONTACT_EMAIL`. Kept only when the licence is CC0, CC BY, CC BY-SA or public domain, the file is JPEG/PNG/WebP/TIFF, landscape (width/height ≥ 1.25), at least 1600 px wide, under 50 MB, and not personality-restricted.
   - **Pixabay** (`PIXABAY_API_KEY`), responses cached 24 hours in `pipeline/.cache/pixabay/`, files downloaded, never hotlinked. Standard keys only get 1280 px files, below the 1600 px floor, so Pixabay contributes only with full API access (`fullHDURL`/`imageURL`).
   - **Pexels** (`PEXELS_API_KEY`), with photographer, photographer URL and photo URL kept as attribution.
     Images already on the site (Images `source_url`, rows' `hero_source_url`) and every source page in `content/image-rejects.txt` (photos the owner turned down) are skipped.
2. **Score**: one vision call (`PIPELINE_IMAGE_MODEL`, default `PIPELINE_MODEL`) sees 768 px previews of every candidate with their source titles, `content/prompts/image-score.md` and `content/image-brief.md` (warm light, low horizon, vineyard or cellar subject; hard rejects for people drinking, raised glasses, parties, people at café or bar tables, HDR halos, logos and labels). It returns a 0–100 score, reject reason and alt text per candidate. The best unrejected candidate at or above `IMAGES_MIN_SCORE` (default 70) wins. About $0.02 a pass.
   If nothing wins, a **broad pass** searches and scores again with `broadQueries`: the wine area (of the page or its town), the region and the département (`DEPARTMENTS` in `pipeline/lib/images.ts`), each with "vignoble" or "vineyards".
3. **Store**: the original is downloaded and converted with sharp to AVIF and WebP at 640, 1024, 1600 and 2400 px (never upscaled, so a 1920 px source stops at 1600). EXIF, ICC and XMP are kept; WebP and AVIF can't carry an IPTC-IIM block, so when the source has no XMP a packet with IPTC Core creator, credit, rights and source is added. Files go to Vercel Blob at `images/<tab>/<slug>-<hash>-<width>.<ext>`.
4. **Write**: the row gets `hero_image` (the largest WebP; next/image resizes it to the site's widths), `hero_credit`, `hero_license`, `hero_source_url` and `hero_is_ai=FALSE`; the Images tab gets `url`, `alt`, `credit`, `license`, `source_url`, `is_ai`, `used_on` (the page path). Missing `hero_source_url` and Images columns are added. One revalidate call follows.
5. **Share a parent's hero**: a row still without a pick after both passes takes the hero of its nearest published parent page that has one: for an article its town, then the town's wine area, then the region; for a town its wine area, then its region; for a wine area its region. The hero columns are copied, and the page's path is added to that image's Images `used_on` (a comma-separated list), so `/image-credits/` shows every page an image is on. A row with no parent hero is left without one and listed as `none`.

To turn a photo down for good, add its source page URL to `content/image-rejects.txt`, clear `hero_image` on the rows that use it and run `images` again.

### Reviewing before writing

Pages that already have a hero (for example ones sharing a parent's) are skipped unless named. To try again for some of them and review the result before anything is written:

```sh
# 1. Search and score again, write nothing; the report and previews land in pipeline/.dry-run/images-<time>/
npm run pipeline -- images --dry-run --redo --only Towns/troyes,Articles/burgundy-with-kids
# 2. Apply only the picks you approve, exactly as reviewed: no new search or scoring, no API cost
npm run pipeline -- images --from pipeline/.dry-run/images-<time>/picks.json --only Towns/troyes
```

`--only` takes slugs or `Tab/slug`; use `Tab/slug` where a slug exists in two tabs (the Chablis wine area and town). `--redo` and `--from` both need `--only`, and `--from` refuses a name with no pick in that file. Re-scoring can pick differently from one run to the next, which is why approved picks are applied with `--from` and not by running `--redo` for real. When a page moves to a new photo, its path is taken off the old photo's Images `used_on`. A run stops at the first Anthropic account-limit error (spend limit or credit balance).

Every run writes `picks.md` and `picks.json` (all candidates, scores, notes, the pick, credit and alt) with each pick's preview under `pipeline/.images/images-<time>/`, or `pipeline/.dry-run/images-<time>/` for a dry run, where the AVIF and WebP files are saved instead of uploaded. The site shows the credit with `components/ImageCredit.tsx` under every hero, and `/image-credits/` lists every Images row.

## Card photos (`card-images`)

`card-images [n]` gives up to n published Tours and Hotels rows with an empty `image` a photo for their card. `tours:import` and `hotels:import` run it for everything still missing one (in CI that needs the `BLOB_READ_WRITE_TOKEN` secret and the `IMAGES_CONTACT_EMAIL` variable; without them it logs that card photos wait). Like `images`, **it never generates images**.

1. **Candidates.**
   - **Tours:** the tour's own photos from Viator's Partner API (`GET /products/{code}`, `parseViatorImages`): the operator's and Viator's (`SUPPLIER_PROVIDED`, `PROFESSIONAL`), never travelers' uploads, cover first, each at its largest landscape size (Viator serves up to 720×480). Credited "<operator> / Viator", licence "Viator partner content", source the tour's Viator page. GetYourGuide and Winalist tours have no photo source yet and go straight to step 4.
   - **Hotels:** Wikimedia Commons, searched by the hotel's name and town (`hotelQueries`), with the same licence rules as heroes but a 640 px floor (`CARD_MIN_WIDTH`). Booking.com and Expedia photos aren't used: the site has no licence for them.
2. **Score**: one vision call with `content/prompts/card-image-score.md`: the hero brief's hard rejects (people drinking, raised glasses, parties, bottles or pours as the subject, anything that sells wine), and for hotels a rule that the photo must show that hotel per its source metadata. The best unrejected candidate at or above `IMAGES_MIN_SCORE` (default 70) wins.
3. **Store**: converted and uploaded as heroes are, to `images/tours/<id>-<hash>-<width>.<ext>` or `images/hotels/…`, at the fixed widths up to the source's own (a 720 px Viator photo is stored at 640). The row gets `image` (largest WebP) and `image_credit`; the Images tab gets a line with `used_on` the tour's region tours page or the hotel's town page.
4. **Fallback**: a row with no pick takes its town's hero, else its region's, with that hero's credit, and the card's page is added to the hero's Images `used_on`.

`--only` takes tour or hotel ids (or `Tours/<id>`, `Hotels/<id>`); with `--redo` it also redoes rows that have a photo. To turn a Viator photo down, add its image URL to `content/image-rejects.txt`. Every run writes `picks.json` and each pick's preview under `pipeline/.images/card-images-<time>/` (`.dry-run/` for a dry run, with the files saved instead of uploaded). The cards show `image_credit` over the photo, and `/image-credits/` lists the Images line.

## Tours

The owner chooses every tour: they paste its link into Tours_Inbox, and that is the only step. The code never finds, adds or reorders a tour on its own. `npm run tours:import` does the rest: it turns the links into draft rows, fills them in from the GetYourGuide Partner API, publishes the ones that meet `content/selection-rules.md`, writes their notes and queues ranked lists. The weekly run does the same for anything left in the inbox.

**Sheet rules.** `docs/apps-script-tours.js` (`installToursRules`, run from Extensions → Apps Script) adds dropdowns for `provider`, `region_slug` (from Regions), `category`, `badge` and `status`; limits `rank` to a whole number unique within region + category (archived rows aside) and `why_picked` to 300 characters; and colors a published row red when a field the site needs is empty, amber when `link_flag` or `notes_flag` is set. The category and badge lists are at the top of the script.

## Tabs

The pipeline writes to Queue, Facts, Articles and Towns, and reads Regions, Tours and Hotels. `init` creates Queue, Facts and Queries with these headers, and adds any missing columns to existing tabs.

### Queue (one row per page to produce)

You fill `id`, `target`, `slug` and the page columns; the pipeline fills the rest.

| Column                          | Who      | Meaning                                                                                                                                                        |
| ------------------------------- | -------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `id`                            | you      | Unique id, e.g. `q-epernay`.                                                                                                                                   |
| `target`                        | you      | `articles`, `towns`, `regions` or `subregions`. Towns, Regions and SubRegions rows must already exist in their tabs; Articles rows are created on first draft. |
| `slug`                          | you      | Lowercase ASCII slug of the Articles or Towns row.                                                                                                             |
| `page_type`                     | you      | Articles only: `guide`, `ranked_list`, `hotel_roundup`, `itinerary` or `practical`.                                                                            |
| `region_slug`, `town_slug`      | you      | Scope for research, tours and hotels.                                                                                                                          |
| `category`                      | you      | Optional Tours `category` to filter on (ranked lists).                                                                                                         |
| `target_keyword`                | you      | Search phrase the page targets; copied to Articles.                                                                                                            |
| `notes`                         | you      | Editor brief for research and drafting.                                                                                                                        |
| `stage`                         | both     | See Stages. Blank means `queued`.                                                                                                                              |
| `attempts`                      | pipeline | Failed checks so far.                                                                                                                                          |
| `score`, `findings`             | pipeline | Last check score and findings (JSON).                                                                                                                          |
| `facts_hash`                    | pipeline | Hash of the fact sheet's content (ignores sources and order); `refresh` compares it.                                                                           |
| `draft_json`                    | pipeline | Latest draft: title, standfirst, meta description, body, FAQ, tour and hotel ids.                                                                              |
| `published_at`, `refresh_after` | pipeline | Set by publish; Towns have no such columns, so they live here.                                                                                                 |
| `cost_usd`                      | pipeline | Total API spend on this row.                                                                                                                                   |
| `usage_json`                    | pipeline | Last 40 calls: stage, model, input/output/cached tokens, searches, USD.                                                                                        |
| `error`                         | pipeline | Last error message.                                                                                                                                            |
| `updated_at`                    | pipeline | Last pipeline write.                                                                                                                                           |

### Facts (one row per Queue row)

`queue_id`, `slug`, `researched_at`, `model`, `facts_hash`, `fact_count`, `dropped_json` (facts dropped for missing sources) and `facts_json`, the fact sheet:

```json
{
  "subject": "Épernay",
  "coordinates": { "lat": 49.04, "lng": 3.96, "sources": ["…"] },
  "from_paris": [
    { "mode": "train", "route": "…", "duration_minutes": 75, "changes": 0, "sources": ["…"] }
  ],
  "opening_months": { "months": ["april", "…"], "notes": "…", "sources": ["…"] },
  "tasting_price_eur": { "min": 20, "max": 45, "sources": ["…"] },
  "estates": [
    { "name": "…", "visits": "booking", "tasting_fee_eur": 30, "website": "…", "sources": ["…"] }
  ],
  "nearest_station": { "name": "Épernay", "distance_km": 0.5, "sources": ["…"] },
  "warnings": [{ "text": "…", "sources": ["…"] }],
  "other_facts": [{ "claim": "…", "sources": ["…"] }],
  "sources": [{ "url": "…", "title": "…" }]
}
```

### Queries (keyword backlog)

`query`, `region_slug`, `town_slug`, `page_type`, `volume`, `notes`, `queued`. A list for the editor to plan from. The CLI doesn't read it; promote a query by adding a Queue row and setting `queued` to the Queue id.

### Content tabs the pipeline writes

- **Articles:** `title`, `standfirst`, `meta_description`, `body_mdx`, `faq_json`, `tour_ids`, `hotel_ids`, `schema_type` (from the template), `updated_at`; on publish also `status`, `published_at`, `refresh_after`. New rows are created with `status=draft`.
- **Towns:** `intro_mdx` (the standfirst), `body_mdx`, `faq_json`, `updated_at`; on publish `status`. The town page shows hotels and tours from their tabs itself, so town drafts embed no cards.
- **Regions:** `tagline` (the standfirst), `intro_mdx` (the body), `updated_at`; on publish `status`.
- **SubRegions:** `intro_mdx` (standfirst, then body); on publish `status`. The tab has no `updated_at` or FAQ column.

Place pages (towns, regions, sub-regions) render their own tours, hotels, estates and practical sections, so their templates leave those out.

## Environment

| Variable                                                                 | Default                |                                                                                                                                                                                                                                   |
| ------------------------------------------------------------------------ | ---------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `ANTHROPIC_API_KEY`                                                      |                        | API key.                                                                                                                                                                                                                          |
| `PIPELINE_SERVICE_ACCOUNT_EMAIL`, `PIPELINE_SERVICE_ACCOUNT_PRIVATE_KEY` |                        | Service account with **Editor** access to the Sheet. Separate from the site's read-only `GOOGLE_SERVICE_ACCOUNT_*`. Dry runs fall back to the read-only account if these are unset.                                               |
| `PIPELINE_SHEET_ID`                                                      | `GOOGLE_SHEET_ID`      |                                                                                                                                                                                                                                   |
| `PIPELINE_MODEL`                                                         | `claude-sonnet-5-5`    | Research and drafting.                                                                                                                                                                                                            |
| `PIPELINE_CHECK_MODEL`                                                   | `claude-sonnet-5-5`    | Grading.                                                                                                                                                                                                                          |
| `PIPELINE_BUDGET_USD`                                                    | `25`                   | Spend cap per invocation. Each call reserves a ceiling first (research $0.35, draft $0.25, check $0.08 per pass, two passes per draft) and the stage stops when the next one wouldn't fit. Publish costs nothing and always runs. |
| `PIPELINE_EUR_USD_RATE`                                                  | `1.08`                 | Rate given to the writer and used to verify USD conversions.                                                                                                                                                                      |
| `PIPELINE_PASS_SCORE`                                                    | `80`                   | Minimum check score.                                                                                                                                                                                                              |
| `SITE_URL`                                                               | `NEXT_PUBLIC_SITE_URL` | Where to POST `/api/revalidate/`. Until the domain is live, the `SITE_URL` repo variable is `https://french-vineyard.vercel.app`; see `docs/DOMAIN.md`.                                                                           |
| `REVALIDATE_SECRET`                                                      |                        | Same secret as the site.                                                                                                                                                                                                          |

| `IMAGES_CONTACT_EMAIL` | | `images`: contact address in the Wikimedia User-Agent. Required. |
| `BLOB_READ_WRITE_TOKEN`, or `VERCEL_OIDC_TOKEN` + `BLOB_STORE_ID` | | `images`: Vercel Blob credentials. The OIDC pair comes from `vercel env pull` once the Blob store is connected to the Development environment; the token expires after about 12 hours, so pull again before a run. Not needed for dry runs. |
| `PIXABAY_API_KEY`, `PEXELS_API_KEY` | | `images`: optional second and third sources; skipped when unset. |
| `PIPELINE_IMAGE_MODEL` | `PIPELINE_MODEL` | `images`: vision model that scores candidates. |
| `IMAGES_MIN_SCORE` | `70` | `images`: lowest score that can be picked. |
| `GYG_API_KEY` | | `tours:check`: GetYourGuide Partner API token (`X-ACCESS-TOKEN`). When set, GetYourGuide tours are refreshed from the API instead of by following their links. Optional; set it as a repository secret for the weekly run. |
| `VIATOR_API_KEY` | | `tours:enrich`: Viator Partner API (v2) key, sent as `exp-api-key`. Optional; Viator drafts wait without it. Also a repository secret for the weekly run. |
| `WINALIST_READ_PAGES` | off | `tours:enrich`: `1` lets it read the schema.org data on the Winalist estate page of a pasted experience (robots.txt allows these pages; one request per pasted tour). Winalist publishes no API documentation. Set as a repository variable for the weekly run. |

Locally, `.env.local` is loaded automatically. In GitHub Actions, set the secrets `ANTHROPIC_API_KEY`, `PIPELINE_SERVICE_ACCOUNT_EMAIL`, `PIPELINE_SERVICE_ACCOUNT_PRIVATE_KEY`, `PIPELINE_SHEET_ID` and `REVALIDATE_SECRET`, and optionally the repository variables `PIPELINE_BUDGET_USD`, `PIPELINE_MODEL`, `PIPELINE_CHECK_MODEL`, `PIPELINE_EUR_USD_RATE` and `SITE_URL`.

Prices for the cost log are in `pipeline/lib/cost.ts`; a model missing from that table stops the run rather than spending untracked money. Sonnet-class calls use the server-side refusal fallback (`fallbacks: "default"`); batch requests can't, so a refused batch request becomes an `error` row.

## Files

```
pipeline/
  cli.ts              argument parsing, dry-run report
  context.ts          config, content files, briefs, usage logging
  sheet.ts            the pipeline's Sheet access (cached reads, logged writes, rate limiting)
  claude.ts           streamed calls, pause_turn, fallbacks, batches, budget
  commands/           init, research, draft, check, publish, refresh, run, seed, images
  media.ts            image searches, downloads, sharp conversion, Blob uploads
  lib/                pure functions, tested with Vitest (*.test.ts)
  fixtures/dry-run-queue.json
  launch-queue.json   launch Queue rows (regions, wine areas, towns, guides, itineraries, practical pages) for `seed`
content/
  prompts/            research.md, draft.md, redraft.md, check.md, image-score.md
  image-brief.md      what a hero image should and must not show
  image-rejects.txt   source pages of photos the owner turned down
  templates/          guide, ranked_list, hotel_roundup, itinerary, practical, town, region, subregion
  style-guide.md, banned-phrases.txt, selection-rules.md, research-blocklist.txt
```

Template frontmatter: `target` (`articles`, `towns`, `regions` or `subregions`), `words` (`min-max`), `required_headings` and `required_components` (`|`-separated), optional `max_tables`, `h2_per_tour: true` (ranked lists) and `schema_type`.
